# Results site

An interactive view of the same published results as the README. GitHub Actions builds and deploys it to GitHub Pages on every push to `main` (`.github/workflows/pages.yml`).

## Files

```
site/
  index.html   page shell: header, navigation, footer, and the text of the About page
  style.css    colours (light and dark), layout, the phone layout
  app.js       routing, tables, charts, tooltips; no framework, no dependencies
  meta.json    model families: maker, short mark for the logo tile, optional logo file
  logos/       optional logo images named in meta.json
  data/        generated by tools/build_site.py; gitignored, never edited by hand
```

`tools/build_site.py` writes `site/data/` from `docs/results/`, using the same `entries()` and `primary_group()` as the README. A number on the site therefore always matches the README.

To preview locally:

```bash
python3 tools/build_site.py && python3 -m http.server -d site 8000   # then open http://localhost:8000
```

To edit the site, change `index.html`, `style.css`, `app.js` or `meta.json` and push. The workflow regenerates the data.

## What it shows

Every view starts from the main results, the same rows as the README's tables: official runs at 4 threads, plus `gemma4:e4b` at 2 threads, marked. Filters can switch to the 2-thread runs.

| Page | Contents |
|---|---|
| **Overview** | One-line verdict; key facts (models, cases, passes, device); three picks computed from the data (most accurate; fastest at 80% or more; best answer in under 15 s), each with its rule shown; the top of the leaderboard; the accuracy-against-time chart |
| **Leaderboard** | Every result, ranked. Rank with ties, model with logo and tags, thinking mode, accuracy with its range across passes, challenge accuracy, a cell per track, time per case, memory, peak temperature, timeouts. Sortable columns; filters for thinking mode, thread count, "fits in 8 GB" and a search box. On phones each row is a card |
| **Tracks** | A heatmap of every model on every track, split into control and challenge; a tab per track with its own ranking and its hardest cases |
| **Thinking** | What thinking adds and costs per model: accuracy and time from off to on, the gain in points, the time factor and the extra tokens |
| **Hardware** | Memory against the Pi's RAM and zram; prompt-processing and generation speed; how each case's time splits between reading the prompt and writing the answer; mean and peak temperature against the 80 °C throttling point; 2 against 4 threads; model load time and sustained speed |
| **Cases** | All 65 cases with track, difficulty, the prompt and the expected answer, and how many models passed each one; images for vision cases; sorted by difficulty by default |
| **Model** | One page per model: maker, Ollama name, capabilities, digest; a card per thinking mode and thread count; accuracy per track and per pass; a grid of all 65 cases coloured by how many passes succeeded, with each case's status, time and the start of the answer |
| **Compare** | Any two results side by side: every metric with the difference, per track, and case by case (both pass, only one, neither) |
| **About** | What is measured and how it is scored, the hardware with photos, suite and protocol versions, links to the methodology and the repository |

## Ranks and uncertainty

Accuracy is the share of cases passed on the tracks a model supports, averaged over passes, exactly as in the README. Each result also has its accuracy in each pass. A result's rank is 1 plus the number of results whose *worst* pass beats its *best* pass, so results whose pass ranges overlap share a rank. With 65 cases, one case is 1.5 points.

## Charts and tooltips

Charts are inline SVG drawn by `app.js`, in the README's colours: blue for thinking off, orange for thinking on.

- **Hover or tap** any point, bar or cell for its details. A chart point shows the model and mode, accuracy with its pass range and case count, time per case, memory, peak temperature, accuracy per track and any tags. Clicking opens the model's page.
- **The keyboard** can reach every point: Tab moves between points and shows the same tooltip.
- Hit areas are larger than the marks, so small points in a cluster are easy to select.
- The accuracy chart draws every result the same size, as its maker's logo; thinking on adds an orange ring and the word *thinking* under the name. Every point is labelled beside it where it fits (on phones, a label that can't fit cleanly is left to the tooltip). A switch shows accuracy against peak memory instead of time.

## Logos

- **Site logo** (`site/logo.svg`, also inline in the header and used as the favicon): a processor with a gauge and rising bars inside, for models measured on the device itself, beside a two-tone "Light Eval" wordmark. Redrawn as SVG from the project's own design, so it stays sharp at 16 px.
- **Overview illustration** (inline in `index.html`): an original drawing of a small single-board computer running an "LLM" beside a monitor showing a benchmark dashboard (latency, temperature, memory, accuracy, tokens per second, prompt latency), with no models or numbers. It deliberately avoids the Raspberry Pi logo and other trademarks, so it needs no credit.
- **Model makers' logos** (`site/logos/`): shown on a white badge in tables, cards and charts, since some are black on transparent. `meta.json` records where each came from: Gemma's icon from Wikimedia Commons (Apache License 2.0, cropped to the star), Qwen's from Wikimedia Commons (CC0), Liquid AI's from its own site. They belong to their makers and only identify the models; the About page says so. A family without a `logo` falls back to a coloured tile with its `mark` letter.

## Phones and accessibility

- The layout works from 360 px wide. Tables turn into cards, charts scale to the screen width, and the navigation scrolls sideways.
- Light and dark follow the system setting, with a toggle in the header.
- Colour is never the only signal: tables carry numbers, and thinking modes have labels as well as colours.
- Layouts are checked by rendering each page at phone and desktop widths in headless Chrome.
